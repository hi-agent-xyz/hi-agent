# 用微信(诚实面对脆弱面)

**Persona:** 用户想让 agent 用微信发消息 / 盯个群,像它用飞书那样。
**Goal:** agent **诚实**报告微信的脆弱:不假装与飞书同等,给出受限路径让用户选。
**Preconditions:** 个人微信号**无开放发送 API** + 强反自动化。对比 [02](02-feishu-sprint-backlog.md)/[03](03-feishu-flash-cards.md)——飞书有开放 API,微信没有,这正是要测的"诚实可行性"([[soft-guidance-no-homegrown-security]])。

## Steps & expected UX

1. **"用微信帮我发 / 盯一下"** → agent **不一口答应**,先说清现实:个人号没有官方发送接口,自动化要么走脆弱的客户端 UI 自动化(违反 ToS、易封),要么用**企业微信 / 公众号**的有限 API。
2. **给选项** → "如果是企业微信 / 公众号场景,我能稳妥接;个人号我只能脆弱地试,有风险——你要哪种?"
3. **用户定** → 选稳妥路径就置备(类 [02](02-feishu-sprint-backlog.md));坚持个人号则**明确风险后**有限尝试,不隐瞒。

## Expected outcome

- 用户拿到一张**诚实的可行性地图**,而不是一个会翻车的空承诺。
- 不在脆弱面上假装与飞书同等可靠。

## Edge cases & failure modes

- 客户端自动化被封 / 失效 → 如实报,不反复硬试。
- 用户坚持高风险路径 → 明确告知风险、留痕,再有限执行。

## Open questions

- 企业微信 / 公众号路径值不值得做成一等能力(像飞书)?
- 个人号自动化的可接受底线在哪(完全不碰 / 仅只读 / 明确风险后试)?
- 一次外发交付,除了"按对方拿到的样子打开那件东西看一眼",有没有可自动化的远端核验?微信与企业微信都没有已读回执,`## On their screen` 也只覆盖上屏的 view。

_机制:effector + 诚实可行性。可行性:**部分 / 脆弱**。成熟度:依赖 effector + 微信路径调研(未建)。_

## 实测 2026-06-18 · origin/main 0f68aaf

- ✅ 教科书式诚实可行性图:"个人微信没官方 API、逆向违反 ToS 易封号,我不建议",随即给企业微信正经 API 路径让老板选。不假装与飞书同等。

## 实测 2026-09-02 · 企业微信"小力"→ 赵力,发一张图

19:43 收到「把小青蛙截图发到我微信」,22:49 才交付出清晰版。**3 小时 06 分,发一张图给它唯一发过东西的那个人。**

- ❌ **收件人被当成必须由人回答的问题。** 20:32 任务记录里已经写明历史只有一个收件人(赵力本人「小力」`single` 单聊),同一时刻仍然转入 `waiting`,要求来者确认"你是否就是历史记录中的赵力本人"。让本人向自己的 agent 自证身份。
- ❌ **自己能清的授权被报成阻塞。** 20:56 对人说"企业微信未授权",引出"难道你的监听都没工作吗";21:03 该 CLI 就从**已经在磁盘上的同一份凭据**自行恢复 `authorized`,全程无人工步骤。收(常驻监听,outbound 禁用)与发(另一套 CLI)本是两条链路,被一个词说成一件事。
- ❌ **发出去的不是截图,是 views 历史带的缩略图。** 21:07 发出的文件与 `data/views/_shots/ref/little-frog-motion/gentle-three-page-story.png` 逐字节相同 —— [view_shots.rs](../../src/foundation/server/view_shots.rs) 强制 DPR 1 渲染后按 `THUMB_WIDTH = 480` 做 Lanczos3 限宽,1512×855 落成 479×271。
- ❌ **核验全部落在传输侧。** SHA-256、上传下载回环、`success: true`、会话哈希逐项通过,21:15 落 `done` —— 没有任何一步打开过那张图。直到 22:27 赵力说"很糊"才被推翻。
- ❌ **一次交付播了四遍。** 21:13 / 21:28 / 22:14 / 22:21,而对方手里那张是糊的。
- ⚠️ **纠错时按错误基准放大。** 22:28 提出 958×542(479×271 的两倍),被当场否掉;22:37 才第一次实测真实尺寸,22:49 按 1512×855 CSS × DPR 2 直出 3024×1710 补发。

**这一条测到的不是 2026-06-18 那件事。** 那次测的是"诚实可行性"(通过);这次暴露的是**真要发一次时的行为**——把自己能做的判断推给人,再用核验的排场盖住没看结果。
