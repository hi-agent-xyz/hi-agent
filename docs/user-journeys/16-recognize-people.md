# 它先认得这张脸 / 这把声音,后来才知道名字,然后处处用得上

**Persona:** 用户和 agent 在不同时间遇到同一些人——摄像头里的一张脸、通话里的一把声音。有的人 agent 早就在记,只是还不知道叫什么。
**Goal:** agent 应当**先凭脸 / 声音把人记成"同一个人"**(完全不需要名字),**名字后来从对话里学到**(老板说"这是赵力"),从此**按名字认人并用起来**(打招呼带名、接上对这个人已知的事);全程**接受模糊**,像人一样。
**Preconditions:** 人脸 / 声纹能力 + people 记忆——每个人是一个目录 `memory/facets/people/<key>/`,放 `facet.md`(散文 facet)+ `face/`、`voice/` 子目录。每条样本是一对**同 uuid 的文件**:原始人脸截图 / 语音片段(`<uuid>.jpg` / `.wav`,媒体是本体)和它的向量(`<uuid>.f32`,可从媒体重算的缓存)——二者同生共灭,画廊严格 1:1(N 个向量 ⇔ N 张图)。画廊是**有界、多样**的集合:每人每模态至多 1000 条,近乎重复的同一张脸 / 同一段声(余弦 ≥ 0.85)只留几条变体,超出按最旧滚动淘汰。**身份模型见 [[project-people-recognition-design]];脸已实测(InsightFace buffalo_l),声音(CAM++)已接通全链路——clip + 实时麦克风(声纹分离)+ reflection 聚簇,待实测。与 [13](13-equip-a-capability.md)(能力分流)、[14](14-knowledge-grows.md)(随用而长)相连。**

## Steps & expected UX

1. **一个陌生人第一次出现**(摄像头里一张脸 / 通话里一把声音)→ agent 当场只当作"一张还没认出的脸 / 一把没听过的声音"(`⟨faces: 不认识⟩`),但**已悄悄把它记下**:反思时机械聚成一个簇,起一个无意义的 id(如 `ff32ce3w`)。**不需要名字就能成为"一个人"。**
2. **同一个人再次出现** → 认出"还是上次那个没名字的人"(同一个簇),不当新人。证据是**软的**:`⟨faces: ff32ce3w ~0.8⟩` —— 分数是线索,不是判决。
3. **老板在对话里点名**("这是赵力,我同事")→ agent 把名字接到那张被记住的脸上(反思时把 `ff32ce3w` **改名**成 `赵力`),从此这人**按名字归档**(`people/赵力`),人也一眼看懂。
4. **此后再遇到** → 直接**按名字认出**("赵力来了 / 在说话的是赵力"),并**用起来**:招呼带名、接上对赵力已知的事(他的 facet、共事经历)。
5. **接受模糊**:角度刁钻的照片、嘈杂的录音、长得像的两个人 → 给"**大概**是赵力"(带分数),不硬下确定结论;允许"看着像、但不百分百",像人。
6. **认错了能纠**:把两个人混成一个、或张冠李戴 → 一句话纠正即可(reflection `hi_merge_people` 合并 / 改名);身份是**可改写的软信念**,不是一锤定音。

## Expected outcome

- **不需要先报名字**就能开始记人;名字一旦学到就**粘住、并被用起来**。
- 认人是**软证据**(分数 + 上下文),由 agent 判断,不是硬分类器;模糊被容忍。
- 归档 key 在没名字时是 id(机器可读),有名字后就是名字(人可读)——同一个人,标签随认知升级。

## Edge cases & failure modes

- 背景里的路人、一闪而过的脸 → 聚成永远没人命名的小簇,无害(可后续清理),不该污染"认识的人"。
- 多人同框 / 多人通话 → 各自聚簇;声音的逐句切分更难(见 Open questions)。
- 低质量(糊、暗、侧脸 / 强噪)→ 宁可"不认识"也不误认(阈值偏保守);**误合比漏认更糟**。
- 命名有延迟:名字落在下一次 reflection(分钟级),不是当场;这点延迟可接受、也像人("回头消化一下就记住了")。

## Open questions

- **声音整套未建**:逐句的干净声纹不好取——流式录音按分钟存、`media:None`,上传片段要解码,多人要切分。自成一档(见设计 memory 的 deferred)。
- 跨模态融合:同一个人脸 0.8 + 声音 0.7,该不该自动认成同一个 `people/<key>`?(目前脸、声各自独立。)
- 命名要不要也能当场(live)做,而不只在 reflection?(现在靠 reflection 把"老板说的名字"和"脸的 id"连起来。)
- 误聚 / 漏聚的阈值、长期没命名 id 簇的清理。(画廊多样性保留已实现:有界 + 近重复变体上限;阈值待真实向量校准。)

_机制:identity = 生物特征簇(**先认人,后命名**)。新脸 / 声 → 机械聚簇,在 reflection 时 mint 一个 id;名字从对话学到 → `hi_name_person` 把 id 改名成名字,`hi_merge_people` 纠错;认人在 hear-time 只读、出软证据,agent 判断。成熟度:**脸已 SHIPPED 且端到端实测**(buffalo_l);**声音待建**。_

## 说明 2026-09-04 · "认人只读"这次才真的成立

上面那句"认人在 hear-time 只读"一直是**意图**,代码不是这么做的:`assign` 一次调用里既找最近的簇又把这条观测写进去,所以实时麦每认一次就入一次库,库再拿自己刚写的东西给下一次打分。本机 `data/memory/facets/people/` 的结果是一个人顶到 1000 条上限、二十五个一秒碎片各自成了一个"人"。

现在拆开了:`recognize` 只读,`cluster` / `enroll` 才写;打分从"对全部样本取 max"改成"最近三条的均值"(max 随库大小单调上升,大簇会靠样本多取胜);判定要有对第二名的领先;实时麦只有 ≥2.5 s 的整段才可能入库,且"认得出但不够确定"的那一段两边都不写。

## 实测 2026-09-04 · 对着本机的库量了一遍(不是 live run)

用一个临时审计页把 `data/memory/facets/people/` 全量向量拉出来两两打分。方法:**留一人测试**——把某条样本自己那一簇整个从库里拿掉,再问剩下的人认不认得它。这模拟"库里没有的陌生人走进来",认出任何人都是误接受。人脸那一侧的"真人"由本人逐条看过确认。

- **人脸完全可分,阈值 0.40 不用动。** 本人逐条认过全部 135 张之后:同一个人最低 **0.293** / 5% 0.548 / 中位 0.819,不同人最高 **0.275**——**两个分布不重叠**;留一人测试在 0.40 到 0.55 之间任何位置都是 **0% 误接受**,误拒 1.5%(0.40)到 5.3%(0.55)。0.40 落在空隙里、两边都有余量。
- **先按未标注的簇算出来的"0.40 误接受 16.5%"是错的,值得记住为什么。** qbatk9nc 和 nbamptgy 本来是同一个人(赵君宁),把其中一簇拿掉后另一簇认出他,被记成了误接受。**留一人错误率只有在"人"确实是人的时候才是错误率**;簇一旦碎掉,它把认对当成认错。
- **所以声音那边的数字目前不可信,0.45 仍是猜的。** 声音的簇正处在同样碎、同样没标注的状态(82% 挤在一个簇内相似度 0.25 的筐里,外加 36 个单样本簇),同一个测试分不清"误接受"和"认回自己"。先标注,再定阈值。
- **声音:库本身是最大的变量。** 未标注状态下 floor 0.45 测出 51.5%"误接受",把赵力那 1049 条的簇整个拿掉后同一阈值变成 7.1%。这两个数都含上一条说的偏差,不能当准确率读;能读的是**方向**——一个占了 82% 样本的松散簇会主导任何测量,也会主导真实识别。**要修的是库,不是阈值。**
- **赵力那一簇不是一个人。** 簇内平均相似度 0.25,其余每簇 0.44–0.73。屏蔽掉它自己之后,它的样本大量落到 **赵君宁**(312 条)——两人声学上分不开,可能是亲属,也可能赵君宁那 87 条里本来就混着赵力。
- **糯米的 7 条声音 0% 认回自己、71% 判成赵力**,是最该先听的一批。
- **124 条声纹 + 32 条人脸向量藏在旧的打包 `.f32` 里,没有媒体**。照常参与打分,但永远没人能核对——只能整条删,不能逐条判。

## 说明 2026-09-04 · 落库的门槛，跟判断的门槛不是一回事

判断可以用它拿到的任何东西——说错了下一句就能改。**画廊是之后每一次判断的评分标准**，所以一条没人能从中认出任何人的片段不该进去，不管它当时被匹配得多有把握。这两件事到 2026-09 才分开。

量了这台机器上已有的 1278 条声音样本：

- **时长和信噪比都挡不住垃圾。** 97% 的样本过 15 dB —— 因为"安静房间里的一声嗯"本身就是很好的电平比。SNR 量的是动态范围，不是"说了多少"。
- **有声秒数才是。** 中位数只有 **1.46 秒**（在 2.75 秒的录音里），最差的是 1 秒里 0.16 秒人声。糯米那 7 条**一条都过不了**，这正好解释了它 0% 认回自己、71% 判成赵力。
- 所以落库要过三道：`VP_ENROLL_MIN_SAMPLES`（2.5 秒录音）、`ENROLL_MIN_VOICED_SECS`（1.5 秒**人声**）、`ENROLL_MIN_UNITS`（转写出至少 5 个字/词）。第三道是唯一能把电视、咳嗽、音乐跟说话分开的——声学只知道"有能量"，只有转写器会说"里面没有词"。按这个尺子，现有的库只有 **46%** 本该进去。
- 人脸这边同样的门槛已经有了（`salient()`：检测分 ≥0.6、≥50 像素），而且人脸的准确率本来就没问题，不动。

**声音样本现在会存下当时说了什么**（`<uuid>.txt`，跟 wav 和向量同 uuid，一起搬、一起删）。「认识的人」界面把它显示在片段下面——**读一遍画廊比听一遍快得多**，也是唯一能一眼看出哪些是句子、哪些是一个音节的办法。

## 实测 2026-09-06 · 人工听过之后：污染是 3%，而且正好落在新规则拒收的那一段

把声音库按新的入库门槛过滤（≥2.5s 录音、≥1.5s 人声、不比本簇中位轻 10dB），1275 条剩 476 条。然后按"对自己簇分数最低"排序，人工听最前面的 6 条 —— **全部不是本人**。

- 这 6 条**都是别人的正常说话**，2.9–5.1 秒、人声 1.7–3.1 秒。质量门槛救不了这种污染。
- 它们**彼此也不是同一个人**（两两相似度中位 0.18）。是好几个陌生人各自被吸进来的一条散尾巴,不是第二个团块 —— 这解释了为什么 `propose_split` 的单链切不开它。
- 赵力 442 条合格样本对自己簇的分数：5% 分位 **0.646**、中位 0.767，**低于 0.60 的只有 12 条**。人听出来的 6 条正是最低的 6 条。
- **这 12 条全部落在 0.45–0.60**，也就是 `recognize_min` 与 `append_min` 之间——新代码"两边都不写"的那一段。旧规则(max 打分、0.5 一刀切)把它们全收了。**新规则一条都不会收。**

**同一份数据否掉了 `frontier_lead`。** 它被写成"正数=这个簇贴着自己的边生长=混了别人"。把这 12 条污染全部剔除后重算：+0.204 → **+0.201**，几乎没动。它跟踪的是画廊有多大多杂，不是有多混；四个画廊分不开这两件事，所以删掉了，只留凝聚度。

**凝聚度这道门也要如实看待**：过滤后赵力是 0.563，在 0.55 之上——**它不会触发**，尽管这个簇确实混了 12 个别人。3% 的陌生人挪不动一个均值。真正挡住这 12 条的是 `append_min`，不是它。凝聚度是给"烂得多得多"的情况留的保险，目前没有任何一个案例证明它会在新规则建出来的库上触发。

## 实测 2026-09-07 · 阈值这条路走到头了，画廊改成有名额的竞争

继续人工听赵力那 442 条(按对自己簇分数升序):**0.648 是本人的妈妈,0.660 是爸爸,0.651/0.656 是小孩哭闹,0.657 也不是本人**;0.641 往后才逐渐"多一些正确的"。

- **污染一直延伸到 0.66,而真样本从 0.60 就开始了。两个分布互相穿插,没有任何一条阈值能分开。** 把 `append_min` 提到 0.68 要丢掉 15% 的真样本,而且仍然不安全。
- **领先量也救不了**:妈/爸/娃对第二名领先 **+0.19 到 +0.40**。它们不是"分不清",是**自信地认错** —— 家里没建簇的人,全库唯一像他们的就是最大的那个画廊。这是开集问题伪装成闭集。

**所以入库不再只看单条分数,而是看名额。** `MAX_SAMPLES` 1000 → **200**,并且满了之后新样本必须从某个在册样本手里赢走位置(`plan_admission`):

- **合群度**用的是对画廊最近 [`SCORE_SAMPLES`] 条的均值,跟识别打分同一个量。**局部性是关键**:缓慢变化的人永远有三个很近的邻居(上周的自己),分数不掉;而"整体上有点像"的陌生人没有近邻,分数天然低。用到质心的距离会把这两者判成一样。
- **门槛自己长**:每进一条就顶掉当前最不合群的一条,而主人说话远多于串门的人,所以下限单调上升。实测:赵力 442 条时下限 0.470,只留最合群的 200 条时下限 **0.774** —— 爸妈那 0.648/0.660 再也赢不了任何一条。**不需要任何人干预。**
- **最新的四分之一不可被顶掉**(`KEEP_RECENT_FRACTION`)。一个正在变化的人,两端的合群度都最低 —— 已经长出去的旧样子,和正在长成的新样子 —— 只有前者是过时的。不保护新的,画廊会一直剪掉自己的前沿,永远停在这个人过去的样子。
- 200 这个数也有理由:识别只读最近的 3 条,再多的样本对匹配没有贡献,却多一个让陌生人藏身的位置。

**重叠说话不再入库。** diarization 只能在时间上分开说话人(按段切片已经在做);两个人同时说,那段波形里是两个声音,嵌入哪个人都不是。真正的分离要上声源分离模型和一个新依赖,而放弃这条样本只损失一条。`acoustics::Room` 本来就从时间段算出了重叠,现在 `worth_keeping` 也读它。

## 说明 2026-09-07 · 入库门槛补到五道；「小声蛐蛐」有两种，都不用绝对音量

人工听下来,过了前三道门的片段里仍有不少"很小声、含糊、像在咕哝"的。这有两个可测的形态,而且**都不需要绝对分贝**——绝对电平在每支麦克风上含义都不同:

- **贴着房间噪底**（`ENROLL_MIN_SNR_DB` = 20 dB）。说话声与它自己的噪底之差,同一次采集里两个电平相减,增益抵消。现有合格样本这个值的 10% 分位是 25 dB、最低 14 dB,所以这道门取的正是最靠近房间的那条尾巴。
- **比这个人刚才说话轻**（`ENROLL_QUIET_BELOW_DB` = 8 dB）。转过头、站在门口、压低嗓子——不是绝对意义上的小声,是"对他此刻而言"的小声。参照物是 `acoustics::Room` 窗口内所有近期发言的电平中位,所以**一个人独自说话时也成立**（跟他自己之前的几句比）；流的第一句没有参照,不判。

另外 `ENROLL_MIN_UNITS` 从 5 提到 **10**:它现在有两个职责,一是唯一能把电视/咳嗽/音乐跟说话分开的门（声学只知道有能量,只有转写器会说"里面没有词"）,二是**要一句话而不是一个词组**——说话人嵌入的好坏取决于取样里音素的丰富程度,10 个字约合 2.2 秒连续说话。

在这台机器的存量数据上量:过了前三道的 476 条里,信噪比那道再刨 13 条、相对音量那道再刨 51 条（去重共 62 条）,剩 414 条。字数那道在旧数据上验不了（当时没存文字），按每秒约 4.5 字折算大约还会再刨最短的一成。**从 1275 条原始样本算起,新规则大概只会留下三成。**

**存量数据仍未清理**,新的打分方式只是不再放大它。清哪些、怎么清,等听完糯米那批和赵力的随机抽样再定。

**行为仍未 live 观测**:上面全是对静态向量库的测量,不是对着真实房间跑出来的。

## 说明 2026-09-07 · 归属这条链上，六处「写了但没接」

把「谁在说话」从入口到落库通读了一遍，改了六处。**全部未 live 观测**，这一节是它们的清单，不是它们的验证。

- **owner 终于能设了。** 之前 `KEY_OWNER` 全树只有三处引用——定义、注释、一次读取——没有任何界面能写，只能改 sqlite。所以 text / file / view 三条 addressed 通道在任何真实安装上都取到空。现在它是「认识的人」页面上的一个动作（`POST /api/people/owner`），指着一个已经在屏幕上的人说「这个是我」，而不是在设置里打一个可能谁都不对应的字符串。**这条动词是 loopback-only**，页面上其余的（命名、剔除、拆分）不是：那些是纠错，这条静悄悄地改变以后每一行打字算在谁头上。
- **语音条和实时麦不再是两套标准。** 语音条原本一次命中 0.45 就落 sender，实时麦要两个 turn 或单 turn 0.60。语音条永远只有一次机会（sender 在投递时定死，不修订），所以它就是「单 turn」那一档，用同一条门槛。`⟨voice: 老王 ~0.47⟩` 这个正文标记照旧写弱的——那是给 mind 的软证据，跟 sender 不是一个东西。
- **串音从一个布尔变成一个量。** 原本任何毫秒级重叠都算「有人插话」，而它只挡入库、不挡识别——于是一段混了两个人的波形照样嵌入、照样投票决定说话人是谁。现在按重叠时长算占比：**任何重叠都不入库**（样本要被之后每一次判断当尺子，少一条不心疼），**只有大比例才不识别**（4 秒里插 300 毫秒的向量只是变脏，分数和 margin 本来就会处理它）。另加一道抖动地板，因为 diarization 的边界是近似的。
- **人脸终于产生 sender。** basis 表从第一天就写着 `cluster` = "a face or a voiceprint matched"，而没有任何一条路径从脸设过 sender：识别结果只写进正文的 `⟨faces: …⟩`，而 settling pass 恰恰不许从正文推断人。查了 git：不是嫌慢——receive-time 人脸识别比归属字段早两个月，presence 现在每 2.5 秒就在跑一次完整的 detect+embed——是那次提交接了音频、漏了视觉，注释还把漏了写成了「认不出来」。**只在画面里恰好一张脸时**才给 sender，两张人脸没有单一答案。
- **presence 那条路故意没动。** 它的显著性判据只有检测置信度 0.6 和 36px，分不出真人和电视里的脸、墙上的照片、小孩在看的视频。现在这些只污染正文文字；给了 grounded sender 就会变成「在场的人」。
- **两个识别器第一次说上话。** 摄像头里恰好一个人、且声音的最高候选就是他，就采信——并且这一个 turn 单独定案，不用等第二个。买到的**只有 margin**：门槛照旧、混杂画廊的否决照旧、店里没提过的名字永远不会凭空出现，分数一个数都不改。**单向**：脸的门槛是量过的（同人最低 0.293／异人最高 0.275，不重叠），声音的 0.45 是猜的，不能拿猜的去定量过的。

**还没被看过的，按重要性：**

1. **两个数字都是猜的，而且一次真实录音能同时量出来**：抖动地板（`OVERLAP_JITTER_MS` = 150ms，要在 diarization 边界抖动之上、真实短插话之下）和污染上限（`OVERLAP_BLEND_SHARE` = 0.5，嵌入从哪个比例起不再属于响的那个人）。太低 → 热闹的房间谁都认不出，这个方向没有底；太高 → 混合向量继续投票，还得靠 margin 兜。`resolve_speaker` 已经把每个 turn 的 `overlap_ms` / `dur_ms` / `share` 打在 debug 日志里，就是为了这次测量。
2. **跨模态那条从没在活的实例上触发过**——要摄像头和麦克风同时开、屋里只有一个已知的人、且声音刚好卡在 margin 上。
3. **人脸出 sender 之后，reflection 会开始为「只是被看到」的人建记录**。这是有意的（在场是边界确立的事实，不是从内容推断的），但没人看过它跑起来什么样。
4. **owner 设完之后，打字消息的头像和 journal 里的名字应该当场变**（读的是 store 不是启动快照），没验过。

## 说明 2026-09-07 · 设备可以登记到人；麦克风不行，而且理由跟设备无关

上一批把 owner 补上之后，剩下的一半是：**远程和本机在归属上完全一样**——手机上打的一行字和键盘上打的一行字拿到同一个默认值。边界一直知道（每个请求都标着是哪个监听器收的，off-box 的还带着具体是哪张凭证），只是没人读。

`surface_credential` 加了一列 `subject`。在「怎么找到它」页面的设备列表里，每台设备可以指定是谁的——从 `/api/people` 已有的人里选，不是打字。在登记过的设备上打的字、递的文件、点开的页面，basis 是 `stated`；**这是这个 basis 从设计出来就留着、一直没有生产者的位置**。没登记的设备什么都不说，落回 owner 默认——**不假定是主人的**，因为别人的手机配过对之后还是别人的手机。

优先级 `cluster` > `stated` > `owner`，按「哪个证据离这一条信号更近」排。登记是 loopback-only，跟声明 owner 同一档：它静悄悄地改变以后所有消息算在谁头上，而门禁允许任何配过对的客户端够到这个路由——不查就意味着一台借出去的手机能把自己登记成主人。收回和改名照旧任何地方都能做，那些是纠错。

**麦克风没跟上，而且不是因为设备形态。** 第一版给每台设备加了第二个开关「这台的麦克风只会录到这个人吗」，想让举到嘴边的手机也能归属它的音频。这是错的，反驳只有一句：**麦克风收的是环境**——地铁上的手机收进来的是地铁，会议室里的手机收进来的是会议。硬件的任何属性都改变不了录音里有什么，所以没有一个开关是人能如实设置的。

剩下一个看着像缺陷、其实是正确答案的不对称：**在登记过的手机上打字有归属，说话没有**。打字是一个人做的一件事，说话是把当时能听见的都录下来——两件事，跟设备远近从来无关。

一条路故意在这套之外：一次性上传页（`POST /api/up/{token}`）在门禁上是开放的，好让没配过对的手机也能用，所以没有任何凭证替它回答，只有 owner 默认。已授权的人把那个二维码给了谁，正是它无法知道的。

**未 live 观测**：登记之后手机上打字是否当场按新身份落账、借来的设备被拒的那条 403、以及旧库升级时那次 `ALTER TABLE`，都只有测试覆盖。
