# 你说"就 A 吧",它马上接着往下做(它备了几条路,你走了哪条它就接哪条)

**Persona:** 老板在跟它**讨论**一件事 —— 不是派活,是来回商量:一个方案怎么定、两个选项挑哪个、一块板上哪里要细看。它刚提了个建议,或者刚把东西交出来,在等他的下一句。
**Goal:** 他的下一句要是走到了**它料到的方向**,它**一秒左右**就动 —— 说它本来就想好的下一段、把他多半要看的东西摆上来、把活交下去 —— 然后照常接着想。他的下一句要是没料到,它就**照常想、照常答**,绝不做出一件对不上的事。
**Preconditions:**
- 一个真跑着的实例(`ssh macmini`,`make build` 之后从 repo 根跑起来)。
- decision 能力有 key。System One 已经是 speech check 在用的判官(`d5dcb0c0`,本机线下 167 条 p50 0.53s、p99 2.2s),但**在活的一轮里从没被看过**。
- `prepared_branches` 默认开(不是 `off` 就读);阈值 `prepared_branches_threshold`,默认 0.9。
- 观察面:wire frames 里 `hi_prepare` 的实参;`GET /api/sessions/events`(和 `data/sessions.jsonl`)里的 `branches_prepared` / `branches_resolved` / `branches_voided` —— 每次读的结果、数、跑了什么;`make measure` 里「备好的分支」那一段(他的话到分支第一个动作的毫秒数)。

底子在 [`docs/arch/agents.md`](../arch/agents.md) 的 *Prepared branches*。和 [34](34-a-step-ahead.md) 是一对:34 让 Cognition 把**下一步的活**提前做好,这条让 Reaction 把**下一步的反应**提前定好 —— 前者省掉等活的时间,后者省掉等一轮的时间。

**模型**:`hi_say` 是**这一刻**的回复。在它之上,Reaction 用 `hi_prepare(matter, branches)` 给**一件事**交上一整组可能的方向 —— 就是一道选择题:每个分支一个条件,加一串它自己的动作(`hi_say`、`hi_show`、`hi_send_message`),**至少一个**。分支之间**互斥**,一句话最多命中一个;同一件事**整组重交**就是换掉,交空列表就是清掉;不同的事各备各的。命中的那个**当场执行**,然后他这句话连同"跑了什么"一起交给 Reaction 正常一轮 —— 它可以接着说、沉默,或者再备下一步。

**一组分支等的是那件事,不是下一句**(09-23 改):他岔开去说 B,A 那组留着;过一会儿回来说 A,照样能命中。他的话**谈到了**那件事 —— 命中就跑,没命中说明事情往别处走了 —— 那组就用掉;没谈到就不动。worker 报告、别的轮、它在别的事上说的话、重启,都**不**作废(存在 `data/memory/prepared.json`)。每一轮的上下文里列着「What you have ready」,过时的由它自己清。最多 4 件事、合计 8 个分支,满了挤掉最老的 —— 按数量,不按时间。

## 为什么是现在

它对一句话做的任何反应,都从一轮生成开始,而一轮到第一句有 **13.8s 的地板** —— 一次上游请求、约 10 万 token 上下文,几乎全是固定成本;从人说完到第一句,中位 **29.1s**([measuring.md](measuring.md) 的基线)。提示词压不动这个数。唯一的办法是**在他开口之前就定好**,他开口那一刻只做一件事:认出是哪一条。

缺的一直是这个"认":要**快**,还要给出**跨调用可比**的把握,阈值才有意义。生成模型做这个要一整轮,自报的把握跟什么都比不了;jev 在本机实测 0.70–0.72s,给的概率是校准过的,0.9 每次都是同一个意思。

## Steps & expected UX

1. **讨论进行中。**它说:"我倾向 A:X 的成本低一半,而且不用改接口。你看呢?" —— 这句**先发出去**。同一轮里,**在这句之后**,它调一次 `hi_prepare`,备下这几条路:
   - "同意 A、没加条件" → `hi_send_message`(交给 Cognition:按 A 开工)+ `hi_say`("好,A。我先写迁移脚本,接口先不动。");
   - "想看 A 和 B 的数字对比" → `hi_show`(那块对比板)+ `hi_say`("我把两边的数摆上来了,差在第三行。")。

   "选 B" 这种到时候再想的方向**不备** —— 没动作的分支命中了也什么都不跑,和没命中一样。

   这些都不进对话,人看不见。
2. **他说"行,就 A"** → 打字一秒左右、说话两秒左右(含识别器 0.8s 的尾静音):活已经交下去了,那句话也到了 —— "我先写"是真的,因为交接那一步刚做完。然后照常一轮:它看到他这句话和"刚跑了哪条、每步结果",可以补一句、沉默,或者备下一组。**不把那句再说一遍。**
3. **他说"给我看看两边的数"** → 板先上屏,再是那句介绍。板要是没摆上(ref 失效),后面那句**不说** —— 它依赖前一步。
4. **他说"对,不过预算得砍一半"** → **没有**任何分支执行。这是给同意**加了条件**,按原样开工就错了。照常一轮,正面接"砍一半"。
5. **他说"对,然后下面按模块分"** → "同意 A"那条**照跑**,紧接着的一轮读到"然后按模块分",接着处理。同意之后**接着往下说**不算加条件。
6. **他说"我觉得 B 更好,因为……"** → 一条都不跑;他谈到了这件事、走向没备,这组**用掉**,之后不会再冒出来。
7. **他转去说别的 / 这时一个 worker 先回了报告 / host 重启了** → 一条都不跑,这组**原样留着**。过一会儿他回来说"A 吧" → 那条照跑。判读时带着这件事当初停在哪句话,所以隔了很久的一句"行"如果紧跟在别的提议后面,算同意那个,不会误命中 A。
8. **他话说到一半停了**("同意。"……两秒后"不过……")→ 要么被"还在说"挡住、整组作废,要么已经执行、他一开口就打断(barge-in);下一轮照常处理他完整的话。

## Expected outcome

- **命中时**:他最后一个字到分支的第一个动作,是**秒级**(打字约 1s,说话约 2s);今天的中位是 29s。
- **一次都没有**:执行了答非所问的分支;"同意但是……"执行了"同意"那条;说出来的话超出了**这一刻已经为真**的范围("弄好了",而其实只是刚交下去);前一步失败了,后一步照说不误。
- **没命中时**,判断本身不加时延(它在 settle 窗口里并行跑)。唯一的代价是写分支拉长了那一轮的尾巴:他在那一轮还没跑完时就回话、又没命中,下一轮就晚开始这么一点。
- 日志里数得出:备了几组、命中几次、每组为什么作废、每次的数。

## 怎么测才算数(别引导证人)

- **不要说"你先把后面的准备好"** —— 那是把答案写进题目。**造情境**:开一场真讨论,它提议,你表态;或者它交一块板,你追问板上的东西。
- **开着量,不另设 shadow**(和 `efa0c512` 删掉所有 gate 的 shadow 档是同一个理由)。要看的数是:命中之后,**紧接着那一轮不得不收回**的比例 —— 改口、叫停交下去的活。这个数按 `p` 分档读,是挪阈值的依据,不是感觉。
- **每条都在对话外核**:wire frames 里 `hi_prepare` 的实参;`branches_resolved` 事件里的 outcome、`p`、`qualified`、`ran`(每个动作的真实结果);`make measure` 的新时刻。
- **反向要测全**:同意加条件、反对、打断 —— 不该执行,且用掉;换话题、中途来报告、重启 —— 不该执行,且**留着**,回来说 A 时要能命中。
- **岔开再回来**:造一段 A → 他转去 B 聊几轮 → 回来说 A。看 `branches_resolved` 里 B 那几句的 `used_up` 是空的、回来那句命中。
- **读字面那条单测**:"行吧,你说了算"、"好啊,随你"。jev 按字面读,这是它最可能判错的地方。

## 本机日志的现状(2026-09-21 粗量,06-14 → 09-21)

- 他对 agent 一句话的**第一条**回复共 548 条。其中跟在**以问句或提议结尾**的 agent 句后面的,只有 36 条(7%);回复中位 32 字;**纯确认(好 / 行 / 对 / 可以……)548 条里只有 3 条**。
- 30 秒内的快回复有 29 条,几乎全是新指令、纠正,或者"对,然后……"。
- 这只量了最窄的一种(纯确认)。分支面向的是**方向**,不只是确认 —— 交一块板之后他多半会追问什么、提议之后他多半往哪边走 —— 这些**可不可预判**,数文本数不出来,只有跑起来的计数量得出。能肯定的只有一条:不命中时必须零成本,而一轮不备分支,就什么都不花。

## Edge cases & failure modes

- **跑错了分支** → 下一轮看到跑了什么和他的话,当场收回:说错的改口,交下去的活叫停(和一次交错了的 hand-down 一样处理)。计数里记一次。
- **房间里别人在聊天**(饭桌上一句"行,就这样")→ 不是他的话:只有麦克风收进来的那一批,会同时问 room screen 的那个问题;判成闲聊就**什么都不跑、什么都不用掉**,事件里记 `side talk`。
- **隔了几天的一组被一句碰巧合条件的话命中** → 这是事项化之后的新风险。防线三道:判读带着这件事停在哪句话;谈到这件事而没命中就用掉;它自己清过时的。够不够,看"命中后被收回"的计数。
- **多人房间,别人替他答了**(是在跟 agent 说,但不是他)→ 谁说的在 state 里,不在规则里。先当已知盲点。
- **jev 没 key、报错、超过两秒** → 不执行、什么都不用掉,走老路。最坏就是今天的速度。(原来是一秒,首批四次读里两次超时。)
- **备太多** → 一次一两条可能的方向;不是把所有可能铺开。
- **分支里的话被 pre-send check 退回** → 这条分支整条不备,不重写。整条,是因为只剩半条(板上去了、介绍没了)不是当初定的那件事。
- **分支备好之前他就回了** → `hi_prepare` 被拒("他已经回了"),照常一轮。
- **他在它还没说完时就插话** → **不作废**。host 判"打断"靠估算(每字 200ms,再加 2 秒余量),所以说完两秒内的快回答也算"打断";要是打断就作废,语音里最该命中的那种就全废了。插进来的话照样拿去跟条件比:"不对,等等"落到 rest,不跑;"行,就 A"就是同意。
- **分支准备时就跑不通**(ref 不存在、句子超长、收件方不在、没有动作)→ **整次调用被拒**,点名是哪条、为什么;之前那组照旧。少一个选项的选择题是另一道题,所以改好了整组重交 —— 在还能改的那一轮里改,而不是等他开口才发现。

## Open questions

- 阈值 τ 从 0.9 起;挪不挪,看"命中后被收回"的比例按 `p` 分档,不拍脑袋。
- 只在语音里开,还是打字也开?打字时 1 秒和 20 秒的差,人没有语音里那么难受;但讨论也可以打字。先都开,看数。
- 紧接着的那一轮要不要看到那次的数?现在只告诉它跑了哪条、每步结果。
- `reaction.md` 里"do not predict what they are about to send"那句,说的是**什么时候说完**,不是**会往哪走**;建的时候要把它对准,不然两条指引打架。

### 09-25 离线量:System One 与 DeepSeek Flash 读同一批停顿

- **「说完没有」光看字谁都判不出**:09-10 以来 80 个停顿(40 个之后两分钟没再说、40 个 20 秒内又接着说),System One AUC 0.56、Flash 0.50。System One 给两类的中位都是 0.81,0.7 的线几乎全判「说完」,还有话的 75% 也被判成说完。这是这道题的上限,不是哪个模型笨 —— 「我想学习了解一下这个概念」是完整的一句,只是他后来又补了一句。
- **`fits`(say / hold / drop)System One 更准更稳**:14 个用例(09-24 的重复、第四问、他改主意、他说到一半…),每个问三遍:System One 39/42、三遍全一致;Flash 关推理 32/42(JSON 自报与 logprob 一样)、开推理 34/42 但 p90 6.6 s。Flash 把换了说法的「词表」重复判成 `say`。
- Flash 只问一个问题时常常不带键名,当时的解析 240/240 判失败。
- **09-26 改问法:不让 Flash 仿 System One 报概率,直接要决定。** 一个 JSON 对象(JSON mode),先写一句 `why`,再写 `finished: true|false` 和每个 `fits` 的选项本身,进地板时当作确定的答案。同一批 14 例 × 3 遍:37/42、3 个用例前后不一(报概率时 32/42、8 个不一),p50 0.95 s、p90 1.16 s。logprob 那种问法(32/42)不再用;开推理不考虑。错的 5 次:「词表」重复 2 次判 say,「说到一半」1 次判 say,「久未回的工作结论」2 次判 hold(这条真值本身存疑,System One 也判 hold)。「说完没有」照样分不开(判对 0.56)。
- **规则本身把它带偏了。** 「连问第四问」Flash 判 hold 的理由是「已经连发三条、门槛高」—— 规则让连发条数压在了一切消息上,包括他亲口问的回答。改成「条数只衡量没人问的消息;他问过的、交代过的工作结果,前面发了多少都照发」之后:第四问两边都是 say/say/say,三个该压的仍全压,两边都 38/42。两边剩下的错多数在「久未回的工作结论」,理由都是「他说要一页一页看页面」—— 这条真值待他定。
- **「说完没有」缺了时间。** 读法只给了字,没给每句是什么时候说的。同 80 个停顿:单看「上一句隔了多久」AUC 0.66,比模型只读字(System One 0.56)还高 —— 连珠炮里前一句中位只隔 20 秒,说完了的前一句中位隔 6 分钟。把时间放进状态(每句标「多久之前」,规则里写怎么读节奏),System One 只到 0.59、Flash 判对 55–56%:给了时间,模型也没怎么用上。已照设计补上(状态里每句带时间)。
