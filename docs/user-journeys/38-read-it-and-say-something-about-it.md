# 一边看它摆上来的东西,一边说话:面板把 view 挤窄,而不是盖住

**Persona:** 桌面用户,1512px 的窗口。agent 刚摆上来一块 board,他想边看边问。
他不想为了打字把 board 遮掉一块,也不想为了看 board 把刚说的话关掉。
**Goal:** 房间(整块 board)· 中间那档(board 窄一点 + 面板)· 整屏面板,
三档之间来回,而且**是他自己在动它**。
**Preconditions:** `wide` 形态(不是窄、或者不是粗指针)。
三个 stop 都有:`room` / `panel` / `full`。
见 [`stage.md` § The panel, and the axis it runs on](../arch/stage.md)。
**与 [37](37-hold-it-in-one-hand.md)(手机只有两档)相连。**

---

## Steps & expected UX

1. **刚打开一个窗口** → 停在**中间那档**:左边是房间,右边 420px 是面板,
   开着 `Messages`。手机开机停在房间,桌面不是——因为桌面原来那个角上的六个按钮
   没了,一块全白的纸没有任何一个看得见的入口。宽窗口装得下两样,那就都给。
2. **agent 摆上来一块 board** → board 排进 **1092px**,不是 1512px 里被盖掉 420px。
   **它是完整的**,只是窄一点:右下角那一块没有藏在什么东西后面。
3. **从右边缘往左拖(或者点一下)** → 面板变成整屏,board 让位。
4. **从左边缘往右拖两次**(或者 `Esc` 两次,或者 `←` 两次)→ 整屏 → 中间档 → 房间。
   到房间时 board 拿回整块 1512px,**上面一个 host 的东西都没有**,
   只剩最新那句话的字幕,几秒后自己淡掉。
5. **随便敲一个可打印的键** → 面板开到中间档、切到 `Messages`、这个字符落进输入行。
   这是桌面第二条进得去的路,而且它一直就在。
6. **鼠标移到窗口最右边 20px** → 那条带子上浮出一根很淡的细线。移开就没了。
   这是**唯一**画出来的入口提示,而且只在细指针上画。

## Expected outcome

- **board 从来不会被盖住**,只会被挤窄——而且挤它的永远是人,不是 agent。
  agent 摆东西不动面板,面板在哪就在哪。
- 一根轴,三档,四种走法(拖 / 点 / `Esc`+方向键 / 打字),没有第二套关法。
- 面板换 tab、换 stop、关掉再开,**对话都停在原来那句上**。

## Edge cases & failure modes

- **中间档时,面板最右 20px 点不着** → 那是「再进一档」的带子。
  这是整根轴上唯一一处真的吃掉了可点区域的地方(房间和整屏都不会)。
- **有的 view 在 1092px 下排不好看** → 认下的代价。一块 view 是照着交给它的框
  编译出来的,1512→1092 是真的换了框。付得起是因为**是人自己拖的**,
  而且再拖一下就是整屏。真要治,是把 view 写成能窄,不是让 host 不敢挤。
- **拖到一半松手** → 就近落档;甩一下 → 顺着方向走**一档**,不会从房间一路甩到整屏。
- **一个 view 抢走了方向键** → 焦点在 view 里的时候方向键是它的(`lib/keyboard.ts`),
  这时候只有边缘手势和 `Esc` 还管用。这是 plane 规则,不是例外。

---

_机制:`lib/panel.ts` 的 `stops("wide") = [room, panel, full]` 和 `settle()`;
`.hi-root[data-stop="panel"] .hi-plane--view { right: var(--hi-panel-width) }`
——**「挤」就是这一条规则**,而且只挂在落定的 stop 上,不挂在拖动过程中。
成熟度:**built,Chromium 无头里看过,真人未用过**。_

## 实测

**2026-09-07,Chromium 无头(1512×900),macOS。** 逐条对过:
开机停在 `panel`;`--hi-panel-left: 1092px`、view plane `right: 420px`;
右边缘点一下 `room→panel→full`,左边缘点一下 `full→panel`;
从左边缘拖 8→900 回到 `room`,从右边缘拖 1505→1000 回到 `panel`;
拖完元素上那个内联的 `--hi-panel-left` **清干净了**(不留一个过期的像素值);
`Esc` 一档一档退;敲 `k` → 开到 `panel` + `Messages` tab。

**真的把一块 view 摆上去看过**:从 `Views` tab 点开 `Stats`,
它在 1092px 里重排,面板在旁边**没盖住它任何一块**;退到 `room`,
它拿回 1512px,屏幕上再没有别的东西。两张截图并排看,重排是干净的。

**没看过的:**

1. **真人在一块全白的房间里找不找得到那条边。** 边缘 hover 的细线在无头里
   截不出来(没有真的指针停留),而这正是零按钮这笔赌唯一的桌面缓冲。
2. 一块**排得不好**的 view 在中间档下什么样。`Stats` 排得很好,不能代表全部——
   要找一块有固定宽表格的。
3. 菜单栏 popover(~380px,`wide` 但只有一栏宽)下中间档退化成整屏对不对。
